## Context

当前仓库已经具备 A 股日线主表、`circ_mv` 字段以及独立的 `moneyflow` side table 审计链路，但还没有一条正式的研究能力把这些数据组合成“主力分歧率最小前十”的月频横截面策略。

现状约束有三点：

- 研究总线 `backend/research/study_runner.py` 能组织窗口和产物，但它默认承接的是现有日频实验入口，不自带月频横截面换仓语义。
- 数据提供层 `backend/core/data/pg_provider.py` 当前只显式提供主表、指数、交易日历、ST 历史等读取能力，没有统一的 `moneyflow` side table 读取接口。
- `moneyflow` 覆盖率并非满覆盖。已有审计显示，近年的单日覆盖率大多在 95% 左右波动，历史早期还存在结构性缺口。如果没有正式的缺失与日期门控规则，最小值排序会把缺失误当成“分歧最小”。

用户本次要的是两件事同时成立：

- 先把因子的数据可用性规则写成明确 spec。
- 基于该 spec 开启 `2016-2026` 十年研究，但不能伪装成系统已经具备的现成功能。

因此本次设计必须同时解决“研究口径固定”和“能力缺口显式暴露”两个问题。

## Goals / Non-Goals

**Goals:**

- 新增一个独立的 A 股月频研究能力，正式定义“主力分歧率最小前十”因子的计算口径、过滤规则、缺失处理和执行时点。
- 为 `2016-2026` 十年研究定义可运行的窗口合同，允许在低覆盖月份显式跳过，并输出完整的月份级诊断。
- 在不修改 `baseline_V10.1` 主逻辑的前提下，补齐该研究所需的 side-table 读取、月频排序与月度持仓执行能力。
- 让研究结果可审计：任何月份是否可交易、为何跳过、样本覆盖率如何，必须进入产物。

**Non-Goals:**

- 不把该因子直接接入 `baseline_V10.1` 或现有日频主线排序链路。
- 不在本次变更中同时研究 signed 版本、positive-only 版本或更多衍生口径。
- 不把 `moneyflow` 缺失补零，也不通过前端重算该研究逻辑。
- 不承诺本次变更自动满足 `2007-2017` 与 `2007-2026` 正式研究门槛；这两个窗口只在后续推广时再纳入。

## Decisions

### D1: 以“独立研究能力”落地，而不是改写 baseline

本次新增能力只面向研究路径，输出独立 study 产物，不改变 `baseline_V10.1` 的默认配置、默认策略和主运行时行为。

原因：

- 这是 L3 研究改动，先固定研究合同，再讨论是否值得推广到主线。
- 当前能力缺口集中在月频横截面与 side-table 读取，如果直接嵌入 baseline，会把“研究验证”和“主线行为”绑在一起，无法归因。

备选方案：

- 直接在现有 multifactor 排序里插入新字段。放弃原因：会污染既有主线，且无法表达月频持仓合同。

### D2: 因子定义固定为“日度分歧率月内均值”

单日因子定义为：

`daily_divergence_rate(t, symbol) = abs(net_mf_amount(t, symbol)) / avg20(circ_mv)(t, symbol)`

其中 `avg20(circ_mv)` 采用截至当日、含当日的过去 20 个交易日流通市值均值。月度因子定义为该股票当月全部有效交易日 `daily_divergence_rate` 的算术均值。

排序口径固定为月末观察日对月度因子升序排序，买入最小 10 只股票。

原因：

- 这是用户明确确认的聚合口径。
- 月内均值比月末单点值更不容易被单日噪声主导。

备选方案：

- 月末最后一日值。放弃原因：更脆弱，对单日缺失更敏感。
- 月内中位数。放弃原因：用户未要求，且会引入额外解释成本。

### D3: 缺失处理采用“严格无效”，绝不补零

以下任一条件成立时，该股票该日 `daily_divergence_rate` 无效：

- `net_mf_amount` 为空。
- `circ_mv` 当日为空。
- 向前 20 个交易日内 `circ_mv` 有任一缺失，无法形成完整 `avg20(circ_mv)`。

月度因子仅在同时满足以下条件时有效：

- 该月月末观察日股票属于可交易候选池。
- 当月至少有 `max(15, ceil(月内交易日数 * 0.8))` 个有效日度值。
- 月末观察日本身存在有效日度值。

原因：

- 该策略取最小值排序，任何 `NULL -> 0` 的补值都会把脏数据直接推到榜首。
- 对月内有效日数设下限，可以阻断“只在少数几天有值”的伪低分样本。

备选方案：

- 缺失补 0。放弃原因：会系统性污染最小值排序。
- 仅要求 1 个有效值即可参与。放弃原因：稳健性太差。

### D4: 日期级覆盖率门控采用“月份分类账”而不是静默忽略

每个候选调仓月份必须先判定观察日是否满足 `moneyflow` 可用性门槛。默认优先使用 `pit_stock_moneyflow_v2_whitelist_daily`；若运行时未接入该表，则必须用等价的覆盖率审计证据重建同口径结论。

观察日满足以下条件时，月份才允许进入排序：

- `moneyflow` 行覆盖率 `>= 0.95`
- `net_mf_amount` 覆盖率 `>= 0.90`

否则该月份标记为 `skipped_low_coverage`，不得进入调仓排序，但必须记录在月份分类账中。

原因：

- 当前 `moneyflow` 覆盖率不是常数，且不同年份差异明显。
- 十年研究需要尽量跑通，但不能靠静默吞掉坏月份伪装完整样本。

备选方案：

- 任一月份不达标即整轮回测报错。放弃原因：会让探索性十年研究完全不可跑。
- 完全不做日期门控。放弃原因：结果不可审计。

### D5: 执行合同固定为“月末观察，次月首个交易日开盘成交”

策略时点合同固定为：

- 在每个月最后一个交易日收盘后，使用当月可见数据计算月度因子。
- 在次月首个交易日开盘买入当月排序最小的 10 只股票。
- 持有到下一次调仓，在下一次调仓日开盘卖出被替换股票。

这与现有系统默认的 `next_open` 成交合同保持一致，不允许在月末收盘价假设同日成交。

原因：

- 与现有研究引擎一致，避免同日收盘成交的未来函数风险。

备选方案：

- 月末收盘买入。放弃原因：与当前系统执行合同不一致。

### D6: 产物必须补齐“月度可用性诊断”

除标准研究产物外，该能力必须新增至少四类月份级诊断：

- `monthly_coverage_ledger.csv`：每个调仓月份的覆盖率、白名单状态、是否跳过、跳过原因。
- `monthly_factor_panel.csv`：参与排序样本的月度因子值、有效日数、月内交易日数。
- `monthly_selection.csv`：每月最终入选 10 只股票及排序值。
- `monthly_universe_stats.csv`：每月可交易样本数、有效因子样本数、被过滤样本数。

原因：

- 这个研究的核心风险不在收益，而在“哪些月份和股票真的可用”。
- 没有月份级 ledger，后续无法判断结果到底来自因子还是来自样本扭曲。

### D7: 十年研究可以启动，但必须显式标注为“部分覆盖可运行”

`2016-2026` 窗口默认允许启动，只在满足以下条件时视为“结果可解释”：

- 跳过月份全部带有明确原因。
- 计划调仓月份中，实际可交易月份占比不低于 85%。
- 运行摘要中显式写出 `planned_rebalance_months`、`tradable_months`、`skipped_months` 与 `partial_coverage`。

若低于 85%，运行可以完成，但必须标记为 `data_unreliable`，不得默认追加到 baseline 报告。

原因：

- 用户明确要求先开十年研究窗口。
- 现有数据覆盖并不支持把“十年跑通”直接等价成“十年结果可靠”。

## Risks / Trade-offs

- [Risk] 月频横截面执行链路需要新能力，落地周期比纯配置研究更长
  → Mitigation：把 provider 读取、月份分类账、排序执行拆成独立任务，先打通最小研究路径。

- [Risk] 采用月份跳过而不是整轮失败，会让收益曲线出现“样本断档”
  → Mitigation：强制输出 `monthly_coverage_ledger.csv` 和 `partial_coverage` 标记，禁止把结果误当成完整连续样本。

- [Risk] 80% 月内有效日阈值与 85% 可交易月份阈值属于研究规则，不是交易所规则
  → Mitigation：在 spec 中固化，并把阈值做成研究配置字段，后续改动必须另开 change。

- [Risk] side-table 读取一旦与主表日期对齐不严，会引入隐性时间错位
  → Mitigation：统一按 `symbol + trade_date` 做 PIT 对齐，并在测试中覆盖月末观察日与次月执行日的日期边界。

## Migration Plan

1. 先新增 OpenSpec 变更工件，固定该研究能力的口径、门控和产物要求。
2. 在研究路径补齐 `moneyflow` side-table 读取与月份级覆盖率判断。
3. 实现独立的月频横截面研究执行器或研究策略适配层，不复用日频 breakout 逻辑做伪月频。
4. 新增 `2016-2026` 研究定义与最小可复现运行命令。
5. 先跑十年窗口，再根据结果决定是否需要扩展到三窗口纪律的其余两个窗口。

回退策略：

- 若实现阶段失败，只保留 OpenSpec 工件，不改 baseline 与产品默认行为。
- 若已新增研究入口，回退时删除独立研究定义和对应运行时代码，不回滚主线数据表。

## Open Questions

- 观察日股票是否还需要额外排除 `STAR`/`北交所` 等板块，当前先遵循“全 A 股 + 既有异常过滤”，不额外新增市场层过滤。
- 月度持仓卖出是否允许“保留仍在前十”的股票并只调差额，当前默认按目标组合再平衡处理。

## D8: 组合构建增加可选的 rank 递减权重模式

本次在现有月频研究执行链路上增加可选的 `weight_mode`，但不改变选股排序口径、执行时点、数据 gate 或默认等权行为。

默认：

- `weight_mode = equal_weight`

新增可选模式：

- `weight_mode = rank_decay_linear`

定义：

- 对 TopN 股票按 `raw_weight = N + 1 - rank` 计算原始权重分数
- 再归一化为目标组合权重
- 目标仓位价值 = 组合开盘总资产 * 目标权重

原因：

- 当前分析已确认 alpha 高度集中在前五只，等权 Top10 会被后排样本稀释
- 递减权重是最小改动，不改变因子、不改变股票池、不改变 TopN，只改变组合内资本分配
- 线性递减权重比更复杂的指数衰减、分层打折更容易审计和复现

实现约束：

- `weight_mode` 必须仅影响调仓目标仓位，不影响 `monthly_selection.csv`
- `monthly_selection.csv` 仍然记录选股 rank，新增权重信息应进入回放产物或 run_meta
- 等权旧 variant 的结果必须保持不变
