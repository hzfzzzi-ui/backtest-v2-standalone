## Context

用户已经明确要求保留阶段式思路，但要显著减少“看不懂、很少用、重复”的配置入口。当前实现只是把部分阶段默认隐藏，并没有真正建立 `config_workspace` 的正式模块边界。

## Goals / Non-Goals

**Goals:**
- 明确 `config_workspace` 的主阶段与高级阶段边界。
- 收紧抽屉职责和阶段说明文案。
- 为后续桌面壳接管准备一个稳定的配置模块边界。

**Non-Goals:**
- 不在本 change 中重算配置 compile 逻辑。
- 不在本 change 中做复杂路由或权限。
- 不在本 change 中一次性重做所有参数表单。

## Decisions

- 决策 1：继续保留阶段式配置，而不是改成完全自由布局。
  原因：这是用户明确保留的工作方式。

- 决策 2：主阶段只保留高频核心配置，高级阶段降到二级入口。
  原因：当前主要问题是信息太多、阶段入口不清。

- 决策 3：阶段说明必须使用极简中文和人话提示。
  原因：前端正式文档已经要求极简中文、少术语。

## Risks / Trade-offs

- [风险] 过度收口导致低频高级参数入口被掩埋
  → 缓解：保留高级阶段二级入口，不直接删除。

- [风险] 旧 rail/drawer 与新 config_workspace 双重存在时间过长
  → 缓解：在 specs 中先锁正式边界，后续 host cutover 时统一接管。

## Migration Plan

1. 先固定正式阶段目录与模块边界。
2. 再在实现阶段迁移旧 rail/drawer 交互。
3. 最后配合桌面壳接管移除旧配置宿主职责。

## Open Questions

- 各阶段内部字段分组仍需在实现前逐页核对，但不影响先定正式边界。
