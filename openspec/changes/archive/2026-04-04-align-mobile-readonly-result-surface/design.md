## Context

移动端现有文档和实现混有“半自动审批执行终端”和“只读结果摘要”两套语义，而正式前端文档已经把移动端收口为只读摘要 + 快速查看结果。为了防止前端两端继续分裂，移动端需要先在文档和接口边界上对齐桌面端。

## Goals / Non-Goals

**Goals:**
- 固定移动端正式角色为只读结果表面。
- 固定移动端与桌面端共享的术语、口径、颜色、状态和错误提示。
- 将审批/执行链从移动结果表面的正式语义中移开。

**Non-Goals:**
- 不在本 change 中重做移动端复杂交互。
- 不在本 change 中重启通知系统。
- 不在本 change 中引入导出或高级对比。

## Decisions

- 决策 1：移动端正式上只读，不承担复杂编辑或运行控制。
  原因：这是已经确认的目标角色。

- 决策 2：移动端与桌面端共享术语和状态合同，不共享壳层 UI。
  原因：文档已经明确两端只共享接口合同和语义，不共享宿主 UI。

- 决策 3：`mobile-daily-briefing` 对齐结果摘要语义，而不是继续背审批工具语义。
  原因：避免移动端角色继续模糊。

## Risks / Trade-offs

- [风险] 旧移动端审批入口仍残留在结果页面语义里
  → 缓解：spec 明确只读结果面边界。

- [风险] 两端颜色/术语仍各自演化
  → 缓解：spec 固定共享字段和状态标签约束。

## Migration Plan

1. 先在 specs 中固定移动端只读结果表面能力。
2. 再在实现阶段调整 dashboard 和 briefing。
3. 最后配合前端整体 cleanup 降级旧移动审批残留。
