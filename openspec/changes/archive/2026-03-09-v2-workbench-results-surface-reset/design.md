## Context

当前结果页存在三类问题：

1. **布局层**  
左侧 9 stage rail 过窄、文字弱、层次不清；顶部摘要是大段文字；回撤图占据核心空间但信息价值低。

2. **交互层**  
旧的 Explain / Execution / Logs 与当前真实使用路径不匹配；用户更需要“个股筛选 NAV、买入漏斗、卖出漏斗、详细交易、日志”这些围绕结果解释的区块。

3. **数据层**  
卖出 reason 目前已有基础数据，但买入漏斗只有总量，没有按 9 stage 的可解释计数，因此前端无法安全地“脑补”逐 stage 漏斗。

因此，这条 change 必须同时定义前端信息架构与后端可观测 contract。

## Goals / Non-Goals

**Goals:**
- 左侧 9 stage 导航改成更宽、更清晰的纵向导航。
- 顶部结果区固定为 8 个 KPI 卡片，字段与后端产物严格对齐。
- 删除独立回撤图，释放首屏给 NAV 主图与个股筛选 NAV。
- 结果诊断改为中文折叠区，默认折叠，点击后平滑展开并滚动。
- 卖出漏斗直接基于 reason 统计展示。
- 买入漏斗基于真实 stage counters 展示，不允许前端猜测。

**Non-Goals:**
- 本 change 不改变回测策略逻辑。
- 本 change 不重写图表库。
- 本 change 不处理配置中心问题，配置来源治理由独立 change 负责。

## Decisions

### D1: 左侧 rail 改为宽胶囊 stage 导航

Stage 导航改为 72~88px 宽的纵向导航按钮，每个按钮包含：
- 数字 badge
- 中文 stage 名称
- 激活态高亮

不再使用单字短标签。

原因：
- 单字 rail 可扫描性太差，且与 9 stage 语义不匹配。

### D2: 首屏只保留 NAV 主图，不再单独展示回撤图

首屏结果区保留 NAV 主图，删除独立 DD 图区域。

原因：
- `最大回撤` 已进入 KPI 卡片。
- 独立 DD 图信息密度低，压缩了更重要的个股与漏斗区域。

### D3: 结果区重排为“8 卡片 + 主图 + 个股 NAV + 折叠诊断”

结构顺序：
1. 8 个 KPI 卡片
2. NAV 主图
3. 个股筛选 NAV
4. 买入漏斗（折叠）
5. 卖出漏斗（折叠）
6. 交易明细（折叠）
7. 日志（折叠）

原因：
- 与用户实际使用路径一致：先看总结果，再看个股，再看为什么买/卖。

### D4: 买入漏斗必须依赖后端 stage counters

买入漏斗展示必须来自后端明确产物，例如：
- `stage_funnel_buy.json`
- 或 `run_meta.counters.stage_buy_*`

前端不得根据已有 `raw_signal / blocked / orders` 自行推断 9 stage 明细。

原因：
- 这属于研究纪律问题，前端脑补会制造伪解释。

### D5: 卖出漏斗按高频 reason 排序

卖出漏斗直接使用 `reason_codes.csv` 或等价产物，按出现次数从高到低展示。

原因：
- 当前数据已经足够支撑。
- 这是低风险、可立即落地的解释层。

### D6: 交易明细与日志改为中文折叠区

移除 Explain；保留：
- `交易明细`
- `日志`

两个区块默认折叠，点击时平滑展开并滚动到区块头部。

原因：
- Explain 概念过泛，且和真实产物不匹配。
- 折叠区比底部 dock 更适合研究台阅读路径。

## Risks / Trade-offs

- [风险] 删除回撤图后，部分用户可能觉得少了一层可视化  
  → Mitigation：在 KPI 中强化 `最大回撤`，并允许后续把 DD 图作为可选折叠区回加。

- [风险] 买入漏斗需要后端补 stage counters，前端重排不能一次性全完成  
  → Mitigation：分两步交付，先落地 UI 容器与卖出漏斗，再接 buy-stage counters。

- [风险] 左侧 stage 导航改宽后会压缩主区宽度  
  → Mitigation：同步优化 drawer 宽度与卡片栅格，确保 1440px 以下仍不炸版。

## Migration Plan

1. 先定义结果页新信息架构和后端计数字段契约。
2. 前端先落地新布局、8 卡片、卖出漏斗、折叠区与个股列表优化。
3. 后端补买入 stage counters 后，再接通买入漏斗。
4. 验证 clean baseline/candidate 在新页面上的可读性和字段一致性。
