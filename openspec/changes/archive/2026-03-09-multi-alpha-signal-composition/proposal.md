## Why

当前后端已经具备统一的 9-stage 运行壳，但多信号组合仍主要依赖单策略特例和符号级持仓状态，尚未形成可复用的组合契约。随着 `55 日突破 + RSI` 等多 alpha 组合进入主线，如果不先补齐组合层与持仓来源归因，就无法稳定地区分“信号有效”“分仓有效”“退出有效”，回测结论也难以审计与复现。

## What Changes

- 新增通用的多 alpha 信号组合能力，在不改变现有 9-stage 编号的前提下，为入场阶段补充统一的组合决策语义。
- 新增来源感知持仓能力，让信号、订单、持仓、退出链路能够保留 `alpha` 与 `sleeve` 归因，避免不同策略互相污染退出口径。
- 扩展公开单次回测主路径，使前端配置可以编译并驱动多 alpha 组合运行，同时保持 baseline 默认行为不变。
- 扩展回测审计与诊断产物，输出组合启停、同股冲突裁决、来源感知退出等最小可验证信息。
- 第一阶段仅收敛并标准化 `breakout_55` 与 `rsi_reversal` 的组合接入方式，为后续增加更多 alpha 模块提供稳定接口。

## Capabilities

### New Capabilities
- `multi-alpha-signal-composition`: 定义多个 alpha 模块如何生成原始信号、进行组合决策，并输出可供仓位构建使用的统一信号集合。
- `source-aware-holdings`: 定义持仓、订单与退出链路如何保留来源归因，支持按来源策略执行退出与审计。

### Modified Capabilities
- `signal-provider-protocol`: 扩展信号提供者协议，使其能够输出带来源元数据的原始信号，并支持多模块组合场景。
- `single-run-pipeline`: 扩展单次回测主路径，使其能够编译、执行并产出多 alpha 组合结果，同时保持现有交易时钟与 baseline 兼容。
- `backtest-audit`: 扩展审计与诊断要求，增加组合决策、冲突处理、来源感知退出和相关 reason_code 的可观测输出。

## Impact

- 影响后端 stage pipeline 契约与适配层，包括入场信号、仓位控制、退出和审计相关对象。
- 影响策略运行时与信号提供者接口，包括原始信号输出、组合输入输出和来源元数据透传。
- 影响回测持仓与订单规划链路，包括持仓归因、组合预算与来源感知退出。
- 影响配置编译链路与运行时配置结构，需要为多 alpha 组合提供稳定的前后端协议。
- 影响产物协议与诊断文件，需要新增可用于 UI 和研究审计的组合与归因字段。
