## Why

当前回测报告和前端工作台中存在大量**看似可用但后端未实现**的功能控件。用户配置后以为生效了，实际上没有任何效果。更严重的是，报告中某些指标（如"个股上限触发: 0"）暗示风控在工作，但实际上根本没有检查。这会导致用户基于错误假设做出交易决策。

此外，报告"§6 策略参数"子表中 ATR 窗口 / ATR 倍数被放在了"信号策略"分类下，但它们是退出止损参数，属于分类错误。

## What Changes

1. **报告修正**：
   - 从"信号策略"子表移除 ATR 窗口 / ATR 倍数（退出规则子表已展示）
   - 仓位分析中"个股上限触发"/"行业上限触发"标注为"未实现"
   - 复合信号子表标注"未实现"

2. **前端控件标注 TBD**：对所有后端未实现的控件添加 `(TBD)` 标记，涉及：
   - 选股范围：日均成交额下限、价格区间、ATR 波动区间、涨跌停规则、行业过滤、成分基准
   - 信号生成：入场趋势过滤（close > 慢线、斜率）、复合信号模块、实时预览
   - 退出规则：退出优先级排序
   - 仓位风控：单票仓位上限、行业仓位上限、现金不足缩量下单

3. **成交价口径**：UI 可选但后端硬编码为 `next_open`，标注为 `(仅 next_open)`

## Capabilities

### New Capabilities

- `tbd-label-system`: 前端 TBD 标注体系——统一的视觉标记方案，标识未实现功能控件

### Modified Capabilities

- `backtest-report-export`: 修正报告中的错误分类（ATR 参数）和虚假指标（未实现的约束统计）

## Impact

- **前端文件**：`index.html`（控件标签）、`report.js`（报告生成逻辑）
- **无后端改动**：本次变更不涉及后端逻辑，纯前端/报告层面
- **无 API 改动**：数据协议不变
