## Context

当前回测工作台（index.html + report.js）在快速迭代中积累了一批 UI 控件，其对应的后端逻辑尚未实现。报告侧也有参数分类错误和虚假指标的问题。本次变更是**纯前端清理**，不涉及后端改动。

涉及两个文件：
- `frontend/index.html` — 控件标签添加 TBD 标记
- `frontend/assets/js/report.js` — 报告 §5 持仓分析 和 §6 策略参数子表修正

## Goals / Non-Goals

**Goals:**
- 用户在前端能清晰识别哪些功能已实现、哪些是占位
- 报告中不再出现误导性指标（如未实现的约束触发次数）
- 报告参数分类正确（ATR 不再出现在信号策略子表）

**Non-Goals:**
- 不实现任何后端逻辑（不补全占位功能）
- 不改变 config 协议或 API
- 不删除 UI 控件（保留占位，只标注状态）
- 不修改后端报告生成器（server-side report）

## Decisions

### D1: TBD 标注方案 — 行内文字 vs CSS badge

**选择：行内文字 `(TBD)`**

理由：
- 控件标签直接追加 `(TBD)` 灰色文字，无需额外 CSS class
- 报告中用 `<span style="color:#999">未实现</span>` 替代虚假数值
- 最小改动量，不引入新的样式系统

替代方案：
- 添加 `.wb-tbd` CSS class + badge 组件 — 过度设计，这批控件未来会逐步实现后移除标记
- 禁用控件（disabled） — 会阻止用户看到默认值，不利于理解系统能力

### D2: 报告 ATR 参数处理 — 移除 vs 移到退出子表

**选择：直接移除**

理由：退出规则子表（line 212-218）已展示 `ATR 止损 (k=2.0)` 和 `追踪止损 (k=3.0)`，完全覆盖了 ATR 窗口/倍数的信息，无需重复。

### D3: 虚假指标处理 — 隐藏 vs 标注

**选择：保留行但标注"未实现"**

理由：
- 完全隐藏会让用户不知道系统计划支持这些功能
- 显示 `未实现` 文字既透明又保留了功能规划的可见性

## Risks / Trade-offs

- **标注过多导致视觉噪声** → 影响有限，TBD 控件集中在选股范围和仓位风控区域，核心信号/退出功能均已实现
- **后端报告不同步** → 本次只改前端 report.js（本地报告），后端 `report_generator.py` 不改。两者目前独立维护，后端报告走 API 路径时不受影响
