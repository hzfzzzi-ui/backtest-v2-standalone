## ADDED Requirements

### Requirement: A2 size-down AB MUST run through the normal stock runtime
The system MUST evaluate A2 buy size-down through the normal stock runtime ledger so orders, fills, cash, positions, NAV, and metrics come from one execution chain.

#### Scenario: A2 variant runs
- **WHEN** an A2 size-down AB variant is executed
- **THEN** buy orders MUST be generated by the normal candidate planning and execution pipeline
- **AND** the variant MUST NOT replay shadow output rows as executable orders

### Requirement: A2 size-down MUST be explicit and default-off
The system MUST only reduce A2 buy size when the dedicated A2 sizing switch is explicitly enabled.

#### Scenario: Existing V3 config runs
- **WHEN** no A2 size-down override is provided
- **THEN** the stock buy sizing behavior MUST remain unchanged
- **AND** A2 diagnostic fields MUST NOT change order quantity or cash planning

### Requirement: A2 label MUST use decision-date observable own-stock data
The A2 label MUST be computed from own-stock data available at the decision date.

#### Scenario: Buy signal is evaluated
- **WHEN** a stock buy signal reaches candidate planning
- **THEN** A2 MUST use decision-date `pre_ret_20d`, `avg_turnover_rate_f_20d`, and `volume_20d_vs_60d`
- **AND** A2 MUST NOT use future returns, realized PnL, TOP30 labels, industry/theme indexes, or study output files

### Requirement: A2 action MUST size down, not veto, matching buys
The A2 action MUST multiply buy order value by the configured scale and MUST NOT remove the candidate from ranking by itself.

#### Scenario: A2 buy matches all thresholds
- **WHEN** A2 size-down is enabled
- **AND** `pre_ret_20d >= 0.50`
- **AND** `avg_turnover_rate_f_20d >= 8.0`
- **AND** `volume_20d_vs_60d >= 1.5`
- **THEN** the candidate planner MUST multiply `order_value_scale` by the configured A2 scale
- **AND** normal lot sizing, cash-aware planning, fill accounting, and later exits MUST continue to apply

### Requirement: A2 conclusions MUST compare same-window stock-leg B0 and A2
The A2 conclusion MUST prioritize same-window stock-leg metrics against B0 before making any research decision.

#### Scenario: A2 results are analyzed
- **WHEN** B0 and A2 experiment ids exist for the same window
- **THEN** the conclusion MUST compare return, CAGR, Sharpe, max drawdown, Calmar, trade count, triggered buy count, and runtime duration
- **AND** it MUST state whether the evidence supports continue, reject, or hold
- **AND** it MUST NOT promote the rule to baseline without explicit user instruction and stronger multi-window evidence
