## ADDED Requirements

### Requirement: Combo AB MUST use unified runtime NAV
The High Chase D5 combo validation MUST run through the unified stock+ETF runtime and build combo NAV from generated component NAVs.

#### Scenario: Combo candidate runs
- **WHEN** the combo AB candidate is executed
- **THEN** the stock component MUST run through the normal stock runtime
- **AND** the ETF component MUST run through the normal ETF runtime
- **AND** the combo NAV MUST be generated by the unified combo runtime
- **AND** the study MUST NOT use `precomputed_component_results` or stock-only NAV as combo output

### Requirement: Combo AB MUST isolate the stock D5 rule
The combo AB candidate MUST only change the stock component High Chase D5 immediate half-exit parameters.

#### Scenario: Candidate payload is built
- **WHEN** the `HC_D5_IMMEDIATE_COMBO` variant is materialized
- **THEN** ETF component runtime input MUST remain unchanged except window bounds
- **AND** stock universe, ranking, entry rules, execution timing, costs, and account allocator policy MUST remain unchanged except window bounds
- **AND** stock runtime `strategy.params` MUST include the explicit High Chase D5 immediate half-exit parameters

### Requirement: Same-window combo conclusion MUST compare B0 replay and candidate
The combo conclusion MUST use the study's same-window B0 replay as its primary decision anchor.

#### Scenario: Study results are analyzed
- **WHEN** B0 and candidate exp ids exist for a window
- **THEN** the report MUST compare total return, CAGR, Sharpe, max drawdown, Calmar, trades, and D5 trigger counts
- **AND** it MUST include stock and ETF component exp ids
- **AND** it MUST state continue, reject, or hold without promoting a baseline
