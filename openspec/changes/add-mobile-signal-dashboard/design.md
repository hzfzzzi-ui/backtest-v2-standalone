## Context

当前仓库的运行形态已经是 `FastAPI + 静态前端`。桌面端首页 `frontend/index.html` 承载的是重型研究工作台，包含参数抽屉、阶段 rail、结果工作台和大量 legacy JS 状态管理；这套结构适合电脑端，不适合直接裁切成手机端。

后端现状有三个关键约束：

1. 现有服务没有认证，任何能访问 HTTP 端口的人都可以读取实验信息。
2. 现有 API 更偏研究工作台原始能力，例如实验运行、artifact 读取、execution preview；没有直接给手机使用的“聚合态买卖指引”接口。
3. 系统已经有可复用的产物基础，包括 `outputs/experiments/index.json`、单实验 `manifest.json`、`portfolio_trades.csv`、`portfolio_daily.csv`，以及 `outputs/market_snapshots/YYYY-MM-DD/market_snapshot.json`。

用户诉求很明确：电脑端保留现有研究能力；手机端通过 HTTP 地址访问；不暴露公网域名；看板聚焦实时查看买入卖出股票指引，用于半自动下单。这里“实时”在当前系统里更准确的实现是“按轮询读取最新实验/最新快照产物”，而不是引入 WebSocket 和盘中撮合。

## Goals / Non-Goals

**Goals:**

- 为手机端新增独立访问入口，不破坏桌面端首页行为。
- 对手机端入口默认施加私网 Host 限制，阻断公网域名和公网 IP 直连。
- 提供最小可用的口令登录与会话认证，避免任何局域网访客直接看到指引。
- 提供面向手机的聚合 API，输出实验摘要、当前持仓、建议买入、建议卖出、风险与市场摘要。
- 复用现有实验产物与执行预览逻辑，避免引入第二套信号生成链。

**Non-Goals:**

- 本轮不做原生 iOS / Android App，也不引入 App Store / 小程序交付链路。
- 本轮不接券商实盘接口，不在手机端直接执行自动下单。
- 本轮不重写桌面研究平台为响应式站点，不拆现有桌面工作台主架构。
- 本轮不保证公网可访问能力，默认目标场景是本机、局域网或私有 overlay 网络访问。

## Decisions

### 决策 1：手机端做独立页面 `/mobile`，而不是在现有桌面页里做响应式折叠

- 选择：新增 `frontend/mobile.html` 及独立静态资源。
- 不选：继续扩展 `frontend/index.html`，试图把 stage rail、参数抽屉和结果区压缩成手机布局。
- 原因：
  - 当前首页是研究工作台，不是内容型看板；直接做响应式会把桌面交互复杂度带到手机端。
  - 手机端目标是快速读信号，不需要桌面端的大量配置控件。
  - 独立页面能保证桌面端零回归，手机端也能按轮询和卡片布局独立优化。

### 决策 2：手机端访问安全分两层，先做 Host 限制，再做口令会话

- 选择：新增私网 Host 中间件，只对白名单私有主机放行；手机端接口再叠加登录态校验。
- 不选：仅靠登录口令，不限制 Host 来源。
- 原因：
  - 用户已经明确要求“不暴露公网域名”，这不是单靠页面登录能解决的，需要入口层就拒绝公网域名。
  - Host 限制可以防止未来误接公网反向代理时，手机端页面被直接暴露。
  - 口令会话则负责处理同一私网内的最小访问隔离。

### 决策 3：登录态采用服务端无状态签名 Cookie，不引入数据库用户表

- 选择：使用环境变量中的口令和会话密钥，生成带过期时间的签名 Cookie。
- 不选：新增数据库表、完整用户体系或第三方 OAuth。
- 原因：
  - 当前需求只有单用户/小范围使用，不需要用户管理后台。
  - 无状态签名 Cookie 足够满足手机端登录、轮询和退出。
  - 这样可以避免改数据库 schema，也不引入外部依赖。

### 决策 4：手机看板信号来自“最新实验产物 + 执行预览 + 市场快照”三路聚合

- 选择：
  - 最新实验摘要来自 `outputs/experiments/index.json` 和实验目录内 `manifest/perf/run_meta`。
  - 当前持仓通过解析 `portfolio_trades.csv` 重建。
  - 建议买卖通过对该实验的配置执行一次 `execution preview`，并与当前持仓做差集。
  - 风险与市场摘要优先读取最近的 `market_snapshot.json`。
- 不选：在手机接口里再次直接调用底层引擎计算完整信号，或者直接把原始 CSV 全量透传给前端。
- 原因：
  - 聚合层可以复用已经稳定的研究产物，不破坏“配置唯一真相”。
  - `execution preview` 已有“候选 + target_positions”语义，适合手机端半自动下单场景。
  - 前端只拿精简 JSON，不直接理解原始 CSV，页面和 API 契约更稳定。

### 决策 5：手机端以轮询更新，不引入 WebSocket

- 选择：前端定时轮询 `/api/mobile/dashboard`。
- 不选：新增实时推送通道。
- 原因：
  - 当前后端没有事件总线或推送基础设施。
  - 手机端关心的是最新信号指引和实验状态，秒级实时性不是必须条件。
  - 轮询足以支撑最小可用版本，也更容易部署在现有 FastAPI 服务中。

## Risks / Trade-offs

- [HTTP 口令登录在明文局域网中仍可能被窃听] → 默认仅允许私网访问，并在文档中明确建议仅在可信局域网或私有 overlay 网络使用。
- [Host 头校验不能代替真实网络边界] → 中间件默认拒绝公网主机，但仍要求部署者不要把服务端口映射到公网。
- [执行预览结果与真实持仓语义存在“下一交易日建议”差异] → 接口返回显式的 `as_of_date_used` 和“建议动作基于下一次执行”的文案，避免误解为已成交事实。
- [历史实验目录不一定总有完整 artifact] → 聚合接口对缺失产物做降级返回，并在页面上显示数据新鲜度和缺口提示。
- [手机端与桌面端状态脱钩后可能出现重复逻辑] → 手机端只消费后端聚合接口，不复刻桌面端 legacy JS 计算逻辑。

## Migration Plan

1. 在后端新增私网 Host 限制和手机端认证/聚合接口，默认只影响 `/mobile` 及 `/api/mobile/*`。
2. 新增 `frontend/mobile.html` 与手机端静态资源，不改动当前桌面首页入口。
3. 接入环境变量：
   - `MOBILE_DASHBOARD_PASSWORD`
   - `MOBILE_AUTH_SECRET`
   - `MOBILE_ALLOWED_HOSTS`
   - `MOBILE_PRIVATE_ACCESS_ENABLED`
4. 发布后通过局域网地址验证：
   - 桌面端 `/` 保持原样可用
   - 手机端 `/mobile` 未登录时只展示登录页
   - 非私网 Host 访问手机入口返回拒绝
5. 如需回滚，只需移除手机端新增路由和中间件；桌面端实验能力不受影响。
