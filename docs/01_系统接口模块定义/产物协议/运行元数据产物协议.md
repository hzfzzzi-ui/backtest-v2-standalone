# 运行元数据产物协议

## 1. 用途

`run_meta.json` 是单次实验的正式运行元数据。
它负责记录本次运行如何被构建、如何被计数、如何被审计。

`run_meta.json` 不是执行合同本身。

## 2. 文件位置

- `outputs/experiments/<exp_id>/run_meta.json`

## 3. 正式收口结构

```json
{
  "exp_id": "exp_20260405_030220276_6afd",
  "tier": "T2",
  "status": "OK",
  "created_at": "2026-04-05T03:02:36.488069",
  "execution_contract_ref": {},
  "provenance": {},
  "data": {},
  "code": {},
  "counters": {},
  "price_adj_mode": "hfq",
  "adj_factor_stats": {},
  "missing_fields": [],
  "warmup": {},
  "asset_context": {},
  "report_consistency": {},
  "universe": {},
  "data_bundle": {},
  "candidate": {},
  "stage_pipeline": {}
}
```

## 4. 必需字段

- `exp_id`
- `tier`
- `status`
- `created_at`
- `execution_contract_ref`
- `data`
- `code`
- `counters`
- `missing_fields`
- `asset_context`
- `report_consistency`

## 5. `execution_contract_ref`

`execution_contract_ref` 只负责定位本次运行实际使用的唯一执行合同，例如：
- artifact 路径
- 合同哈希
- 合同版本

它不得内联 baseline / study / linked experiment 这类来源标签。

## 6. `provenance`

`provenance` 记录来源与组装说明，例如：
- `config_source`
- `resolved_config_mode`
- `resolved_config_id`
- `resolved_config_hash`
- baseline / study / linked experiment 来源
- 组件装配轨迹

`provenance` 只做追溯和说明，不参与执行。

## 7. `data`

`data` 记录本次运行的数据选择与范围，例如：
- 起止日期
- benchmark
- universe 选择
- asset scope

## 8. `code`

`code` 记录本次运行使用的代码形态与执行配置，例如：
- engine mode
- execution profile
- fast mode

## 9. `counters`

canonical counters 必须保持：
- `raw_signal`
- `blocked`
- `orders`
- `skipped`
- `closed_trades`

可扩展计数器允许存在，但不得替代 canonical counters。

## 10. `missing_fields`

`missing_fields` 用来记录协议补齐缺口。它不能被省略，也不能被空文件掩盖。

## 11. `asset_context`

`asset_context` 记录本次实验所属资产域与执行域，例如：
- `asset_scope`
- `asset_profile_id`
- `market_profile_id`
- `execution_profile_id`

## 12. `report_consistency`

`report_consistency` 记录结果与配置的一致性来源，例如：
- `config_source`
- `config_conflict_policy`
- `resolved_config_mode`
- `resolved_config_id`
- `resolved_config_hash`

它属于一致性与来源审计，不属于执行合同。

## 13. 兼容原则

- 允许新增字段
- 不允许删除 canonical counters
- 不允许用旧字段名伪装新协议
- 不允许返回 `NaN` / `Inf`
