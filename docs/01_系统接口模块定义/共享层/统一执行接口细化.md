# 统一执行接口细化

## 0. 定位

本文细化共享层里的四份正式合同：
- `execution_contract`
- `subsystem_budget_v1`
- `action_intent_v1`
- `risk_override_v1`

它们共同约束统一执行链，不再依赖组合来源字段或研究旁路字段。

## 1. 当前正式调用链

```text
execution_contract
-> market_regime_engine
-> global_portfolio_governor
-> subsystem_budget_v1
-> action_intent_v1
-> risk_override_v1
-> execution_kernel
-> target_book_v1
-> execution_audit
```

## 2. `execution_contract`

作用：定义本次实验唯一的正式执行真相。

它必须是纯参数合同。
它不得包含以下字段：
- `baseline_id`
- `study_id`
- `linked_exp_id`
- `source_kind`
- `source_mode`
- `runtime_entry_mode`

## 3. `subsystem_budget_v1`

作用：描述单个子系统在当前组合中的正式预算盒。

## 4. `action_intent_v1`

作用：描述子系统在预算盒里的正式动作意图。

## 5. `risk_override_v1`

作用：描述 Governor 面向执行层发出的正式覆盖合同。

## 6. 当前不允许的回流

以下内容不应从执行层反向写成上游正式合同：
- 子系统私有排序结果
- 研究诊断字段
- 历史兼容字段
- provenance / reference 字段
- 非主线桥接字段

## 7. provenance 与展示层

`component_source_contract`、`component_experiments` 与 `comboTruth` 可以存在，但职责受限：
- `component_source_contract`：只负责组件装配与来源说明
- `component_experiments`：只负责记录引用到的上游实验
- `comboTruth`：只负责结果展示

它们都不是执行合同。
