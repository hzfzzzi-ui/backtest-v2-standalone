# 执行审计接口定义

## 0. 定位

本文件定义共享执行层的正式留痕合同。
它回答三个问题：
- 当日接收到了什么动作与风控覆盖
- 哪些动作最终进入 `target_book_v1`
- 哪些动作被拒绝、截断、覆盖或取整

它不负责：
- 子系统研究解释
- 候选阶段排序
- 组合重建逻辑

## 1. 正式职责

`execution_audit` 是执行层正式输出的一部分。
它必须能回溯：
- 每条普通动作的最终命运
- 每条风控覆盖的最终命运
- `target_book_v1` 之外的失败、拒绝、截断与覆盖

## 2. 调用边界

当前共享执行边界理解为：

`action_intent_v1 + ordered risk_override_v1 -> execution_kernel -> target_book_v1 + execution_audit`

其中：
- `action_intent_v1` 表达普通动作意图
- `risk_override_v1` 表达 Governor 覆盖
- `execution_kernel` 只做共享执行裁决与落地
- `execution_audit` 保存正式留痕

## 3. 正式字段

`execution_audit_v1` 至少应包含：
- `contract_version`
- `decision_date`
- `execution_date`
- `cash`
- `action_results[]`
- `override_results[]`

### 3.1 `action_results[]`

每条动作审计至少包含：
- `source_intent_id`
- `owner_system`
- `priority`
- `action_index`
- `symbol`
- `side`
- `suggested_size_value`
- `suggested_size_unit`
- `suggested_size_basis`
- `status`
- `status_reason_codes`
- `rounded_to_lot`
- `clipped_to_sellable`
- `blocked_by_override`
- `final_order_qty`
- `final_target_weight`

### 3.2 `override_results[]`

每条覆盖审计至少包含：
- `override_scope`
- `target_symbol`
- `override_action`
- `status`
- `reason_codes`

## 4. 语义约束

- `execution_audit` 必须记录当日收到的全部普通动作，不得只记录失败动作
- `execution_audit` 必须记录当日收到的全部 `risk_override_v1`
- `execution_audit` 不得把被覆盖或被截断的动作静默吞掉
- `source_intent_id` 必须全局唯一
- `execution_audit` 不得成为研究层的替代品

## 5. 与 `target_book_v1` 的关系

- `target_book_v1` 只保留最终幸存动作
- `execution_audit` 保留全部动作与覆盖的留痕
- 二者共同构成执行层正式真相

## 6. 代码映射

当前正式映射：
- `backend/core/stage_pipeline/adapters/daily_accounting.py`
- `backend/core/audit/attribution_audit.py`
- `backend/core/stage_pipeline/adapters/order_planning.py`
- `backend/core/portfolio/portfolio_runtime.py`

## 7. 不收录为正式合同的内容

以下内容只可作为内部调试或研究辅助，不可写成执行审计正式语义：
- 研究阶段的排名解释
- 候选阶段的排序细节
- 子系统私有分数
- 重构历史叙事
