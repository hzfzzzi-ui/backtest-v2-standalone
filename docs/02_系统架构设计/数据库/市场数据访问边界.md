# 市场数据访问边界

## 0. 文档定位

本文档用于定义市场数据域的正式访问边界，回答：

- 上层到底应该如何消费市场数据
- 哪些旧入口属于过渡壳
- 统一市场数据访问层应该覆盖哪些能力
- 跨市场扩展时访问合同如何保持稳定

## 1. 正式原则

市场数据正式消费入口固定为：

- `canonical_market`

研究 / 回测默认只消费 `canonical_market`，不再让以下概念作为并列正式上层入口长期存在：

- `v1`
- `v2_runtime`
- `data_role`
- `stocks_table`
- `stocks_mapping_table`

这些对象当前只允许作为迁移期实现细节或审计回显存在。

## 2. 禁止事项

市场数据访问层正式上禁止以下行为：

- 应用主路径直接 `psycopg.connect` 查询市场数据表
- 业务模块自行拼接 `pams_ohlcv_daily` / `pams_ohlcv_daily_v2` / `pit_*` 查询
- 在上层配置中继续把 `data_role` 当长期正式用户接口
- 在新配置中继续把 `pams_ohlcv_daily_v2_runtime` 当目标消费表
- 把 `pams_ohlcv_daily` 继续当默认正式主路径

## 3. 统一访问层职责

统一市场数据访问层长期应成为市场数据域唯一正式入口，至少负责：

1. 价格序列访问
2. benchmark 访问
3. PIT 指数成分访问
4. PIT 行业历史访问
5. 交易日历访问
6. 证券主数据访问
7. 跨市场 schema 映射
8. 访问审计与来源回显

这些能力应按业务能力命名，而不是按底表命名。

正式语义更接近：

- 取价格历史
- 取 benchmark 历史
- 取交易日历
- 取 PIT 成分
- 取 PIT 行业历史
- 取证券主数据

而不应继续暴露为：

- 读某张 `pams_*` 表
- 读某张 `pit_*` 表

这意味着下列能力最终都应统一收口，而不是分散在各模块里各自直查：

- `PostgresDataProvider`
- universe resolver 内的 `pit_index_constituents / pit_industry_history` 查询
- market snapshot service 的价格与日历查询
- 各类 query service 中的直接行情 SQL

### 3.1 查询形态

各能力的正式查询形态当前收敛为：

- `价格历史`：支持单标的与批量
- `证券主数据`：支持单标的与批量
- `benchmark 历史`：支持单标的与批量
- `PIT 成分`：保留 `as_of_date` 快照与 `window` 历史切片两类能力，其中快照是主能力
- `PIT 行业`：保留 `as_of_date` 快照与 `window` 历史切片两类能力，其中快照是主能力
- `交易日历`：只保留批量能力

### 3.2 `benchmark` 统一能力

`benchmark 历史` 正式上采用同一业务能力，不再拆成：

- 指数接口
- ETF 接口

底层实现允许按对象类型分流，但合同层不再分裂成两套正式接口。

## 4. 正式输入与审计回显

### 4.1 正式输入维度

统一市场数据访问合同当前应固定以下输入维度：

- `asset_scope`
- `market`
- `data_level`
- `as_of_date` 或 `window`
- `symbols`

其中：

- `data_level` 当前正式只支持 `L1`
- `L2` 当前无正式数据，不进入现阶段正式合同

### 4.2 访问审计回显

统一市场数据访问层正式上至少应回显：

- 实际命中的 canonical 对象
- 时间窗口
- 市场
- 是否降级
- 是否缺数
- 查询版本
- `cache_hit`
- `cache_version`

### 4.3 交易日历最小口径

交易日历当前正式上只保留最小口径：

- 交易日序列
- `is_trading_day`
- `calendar_version`

当前不把半日市、特殊交易日标签等扩展信息纳入正式合同。

## 5. 最小正式返回字段

### 5.1 价格历史

`价格历史` 的最小正式返回字段收敛为：

- `date`
- `symbol`
- `open`
- `high`
- `low`
- `close`
- `volume`
- `amount`
- `adj_factor`
- `is_suspended`

这些字段用于承接当前正式 L1 行情真相，不再要求上层通过底表差异自行拼装。

### 5.2 `benchmark` 历史

`benchmark 历史` 复用与 `价格历史` 相同的最小正式返回结构，不再单独定义一套更小字段集。

正式目标是：

- 指数 benchmark
- ETF benchmark

在合同层共享同一输出结构，底层实现允许分流。

### 5.3 `PIT 成分`

`PIT 成分` 的最小正式返回字段收敛为：

- `index_code`
- `symbol`
- `start_date`
- `end_date`
- `as_of_date`

其中：

- `as_of_date` 快照是主能力
- `window` 历史切片与其共享同一最小字段面

### 5.4 `PIT 行业`

`PIT 行业` 的最小正式返回字段收敛为：

- `symbol`
- `industry_l1`
- `industry_l2`
- `standard`
- `start_date`
- `end_date`
- `as_of_date`

其中：

- `as_of_date` 快照是主能力
- `window` 历史切片与其共享同一最小字段面

### 5.5 证券主数据

`证券主数据` 的最小正式返回字段收敛为：

- `symbol`
- `ts_code`
- `name`
- `market`
- `exchange`
- `security_type`
- `asset_scope`
- `list_date`
- `delist_date`
- `is_active_at_asof`

正式上将：

- `name`
- `asset_scope`

都提升为必返字段。

当前不把更细的主题标签、行业扩展字段和研究辅助字段纳入最小正式返回面。

## 6. 缓存语义

访问审计中的缓存语义正式上收敛为：

- `cache_hit`：必返布尔字段
- `cache_version`：必返字符串字段

固定解释：

- 若直接命中 canonical、未经过缓存命中链路，则 `cache_hit = false`，`cache_version = "direct_canonical"`
- 若经过缓存链路但未命中，则 `cache_hit = false`，`cache_version` 返回所用缓存命名空间或版本
- 若命中缓存，则 `cache_hit = true`，`cache_version` 返回所命中的缓存命名空间或版本

不再使用空字符串或缺失字段来表达缓存语义。

## 7. 当前过渡壳

当前市场数据访问仍存在几类典型过渡壳：

### 7.1 `data_role`

当前 `data_role` 同时承担：

- 用户可选数据源角色
- 表名切换开关
- 审计回显字段

这是过渡设计，不应继续作为长期正式合同保留。

当前实现状态已经比文档早一步：

- 新配置默认入口与主研究/回测读取面已收向 `canonical_market`
- `market_data_access` 已进入主路径
- `data_role` 仍在少数 compile、审计回显和兼容草稿路径中存活

因此，`data_role` 当前的正式定位应理解为：

- 已降级为 compat 字段
- 尚未从实现中完全删除
- 不得再被新增逻辑当成正式用户接口

长期方向：

- 删除 `data_role` 作为正式用户接口
- 改为更稳定的市场数据访问合同

### 7.2 `pams_ohlcv_daily`

`pams_ohlcv_daily` 当前仍被大量配置和脚本当成默认价格主表。

正式定位应收敛为：

- 历史参考表
- 迁移对象
- 审计对照对象

长期目标是完全退役，不再作为正式默认主路径。

### 7.3 `pams_ohlcv_daily_v2_runtime`

`pams_ohlcv_daily_v2_runtime` 只允许服务旧 baseline 迁移期。

正式约束：

- 不允许新配置继续把它当正式目标表
- 不允许它继续扩成长期正式层
- 后续应尽量被 `canonical_market` 或统一市场数据访问层吸收

## 8. 跨市场骨架

统一市场数据访问层从文档层面，当前应预留跨市场统一访问骨架，但不把 `L2` 伪装成已存在正式层。

1. `CN_A_L1 canonical`
2. `US_L1 canonical`
3. `cross_market_access_contract`

建议理解为：

- `L1 canonical`：日频 / 基础行情 / 标准可回测行情真相
- `cross_market_access_contract`：跨市场统一访问语义与回显语义

当前不把 `L2 canonical` 纳入正式范围；未来若接入 `L2`，应作为独立扩展增补到同一访问合同之下，而不是提前把空层写成已落地正式能力。

不同市场不要求共享同一张物理表，但必须共享同一套正式访问边界。

## 9. 当前实现偏移

当前实现相对目标边界，至少有这些偏移：

1. 默认配置仍大量指向 `pams_ohlcv_daily`
2. `data_role` 仍是少数运行配置和审计路径中的显式 compat 字段
3. `PostgresDataProvider` 与少量历史入口仍保留按表名解析的 compat 行为
4. `universe_resolver`、`market_snapshot_service` 等主路径已开始通过统一访问层收口，但仍应继续排查低频直连查询
5. `pams_ohlcv_daily_v2_runtime` 仍在实现层作为旧 baseline 迁移期可选入口存在

所以当前最需要的不是再增加新的表名开关，而是收掉上层对旧入口的依赖。

## 10. 推荐迁移顺序

建议迁移顺序：

1. 先把新配置默认入口从 `pams_ohlcv_daily` 收到 `canonical_market`
2. 再把 `pams_ohlcv_daily_v2_runtime` 限定到旧 baseline 迁移期
3. 再把 `data_role / stocks_table / stocks_mapping_table` 从上层合同里拔掉
4. 最后统一收口 `PostgresDataProvider`、PIT 查询和 benchmark / calendar 查询入口
