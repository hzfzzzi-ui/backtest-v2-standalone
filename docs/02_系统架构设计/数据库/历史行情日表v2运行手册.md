# `pams_ohlcv_daily_v2` Runbook

## 目标

本 runbook 用于：
- 建表与回滚
- 单段 smoke
- `v2` 全历史 raw/main/moneyflow/audit 正式回填
- 宿主机侧查看 `exit_code / heartbeat / OOMKilled / status`

### 正式审计

正式 formal audit 固定三窗口为：
- hard gate `2016-2026`：`2016-03-01 ~ 2026-03-20`
- hard gate `2012-2017`：`2012-01-04 ~ 2017-12-29`
- advisory `2012-2026`：`2012-01-04 ~ 2026-03-20`

单独补齐 formal audits：
```powershell
docker exec backtest-v2-standalone python -m backend.cli data_refresh --target pams_ohlcv_daily_v2_formal_audits -- --output-dir outputs/ops/v2_formal_audits_20260322 --apply
```

如果走正式全量回填，`full_backfill` 只会在“全窗口且非 symbol smoke”时自动追加 `audit_formal_windows`，不会把局部回填误记成 hard gate 已补齐。

formal audit 的 canonical gate 现在会同时输出：
- `critical_exception_rows_raw`
- `known_source_gap_rows`
- `critical_exception_rows`

symbol 级 formal audit 只统计与当前主表 `build_run_id` 对齐的 current exception。  
如果异常表里残留了旧 run 的 symbol 级异常，而主表同一 `symbol/trade_date` 已被后续重建修复，这类 stale exception 不再进入 formal gate summary。

其中 `BJ pre-2021-11-15` 的 `turnover_rate_imputed_zero + bj_pre_daily_basic_gap` 只会进入 `known_source_gap_rows`，不会再计入 hard gate 的有效 `critical_exception_rows`。  
注意：runtime 仍会把这批行作为 `known_source_gap_low_turnover` 排除，不能据此视为 runtime 已放开。

`BJ post-2021-11-15` 的 `turnover_rate_imputed_zero + bj_post_daily_basic_gap` 也按同一原则处理：  
- canonical gate 计入 `known_source_gap_rows`，不再算作 hard gate 的有效 `critical_exception_rows`
- runtime 仍继续排除，traded 行可见性会落在 `known_source_gap_low_turnover`
- `synthetic_gap_fill` 行仍优先按 `row_status_synthetic_gap_fill` 排除

`pre_close_imputed_zero + left_censored_anchor_gap` 也按 known source gap 处理，但只适用于 `synthetic_gap_fill / suspended_confirmed / delist_tail_confirmed` 的窗口起始连续缺锚点样本：  
- canonical gate 计入 `known_source_gap_rows`，不再算作 hard gate 的有效 `critical_exception_rows`
- runtime 继续按 `low_pre_close_confidence` 排除，不会因此放开默认消费
- `source_unresolved` 样本不得仅因为同时出现 `pre_close_imputed_zero` 就并入这条规则

`turnover_rate_imputed_zero + left_censored_turnover_gap` 与上面的 `pre_close` 左截断样本是同一批 `SH/SZ` 非 traded 样本：  
- 只在 `synthetic_gap_fill / delist_tail_confirmed` 且 `pre_close_source = imputed_zero` 时按 known source gap 处理
- canonical gate 计入 `known_source_gap_rows`，不再算作 hard gate 的有效 `critical_exception_rows`
- runtime 不新增特殊放宽，这批行仍先按 `row_status_synthetic_gap_fill / row_status_delist_tail_confirmed` 排除

## 状态文件

launcher 运行后会在 `outputs/ops/<run_name>/` 下生成：
- `launcher_status.json`
- `worker_container_state.json`
- `worker_container.log`
- `worker_container_name.txt`
- `exit_code.txt`

容器内 full-backfill runner 会继续写：
- `status.json`
- `failure.json`（失败时）
- `heartbeat.json`
- `current_step.txt`
- 各 step 子目录下的 `summary.json`

formal audit runner 额外写：
- `summary.json`
- `audit_2016_2026/summary.json`
- `audit_2012_2017/summary.json`
- `audit_2012_2026/summary.json`

### 关键判断

- `exit_code.txt` 不存在：launcher 自身未完整收尾
- `exit_code.txt = 0`：worker 进程正常退出
- `launcher_status.json.status = failed_oom`：worker 容器被 OOM kill
- `heartbeat.json.updated_at` 长时间不变：优先查当前 step 是否卡住
- `worker_container_state.json.OOMKilled = true`：本次失败根因是容器级内存杀掉
