# 前端接口边界

## 1. 文档定位

本文档定义当前前端各模块之间的正式边界。

## 2. 当前正式 owner 链

桌面前端当前正式 owner 链为：

1. `frontend/index.html`
2. `frontend/assets/js/desktop-shell/host.js`
3. `frontend/assets/js/desktop-shell/runtime-surface.js`
4. `frontend/assets/js/desktop-shell/app-shell.js`
5. `frontend/assets/js/desktop-shell/*workspace.js`
6. `frontend/app/results-workbench/`

各 owner 分工如下：

- `host.js`：共享状态 bootstrap owner
- `runtime-surface.js`：共享 helper / runtime owner
- `app-shell.js`：页面级 init / bridge / 事件装配 owner
- `config-workspace.js`：配置工作区 active owner
- `run-orchestration.js`：运行、加载、保存、hydrate 编排 owner
- `results-workspace.js`：桌面结果快照与结果桥接 owner
- `history-workspace.js`：历史结果列表与历史加载 owner
- `results-workbench/`：可见结果区渲染 owner

## 3. 统一 app state 边界

桌面端正式上只允许一套共享 app state。

规则：

- 各模块不得各自维护独立主真相 store
- 运行、加载、hydrate 统一由 orchestration 层写回状态
- 结果工作台只消费统一状态，不自行发明第二套真相

## 4. API adapter 边界

正式规则：

- UI 组件不得直接 `fetch`
- 页面模块不得直接 `fetch`
- 结果工作台不得绕过统一 adapter 直接请求业务接口
- 所有后端调用都必须经由统一 API adapter / data service

## 5. 结果数据边界

当前结果真相面为：

- `comboTruth`
- `execution_contract` 或 `execution_contract_ref`
- provenance / assembly metadata（可包含 `component_source_contract`）
- 正式绩效产物
- 正式审计产物

## 6. 配置边界

当前 unified combo 配置边界为：

- 顶层 wrapper 可包含 `asset_scope`、`asset_context`、`unified_runtime`
- 前端展示组件来源时，以 provenance / assembly metadata 为准
- 前端解释运行行为时，以 `execution_contract` 或 `execution_contract_ref` 为准
- 前端对 unified combo baseline 采用 source-preserving handoff
- 前端不得把 unified combo baseline 重建成单资产草稿

## 7. 前端硬约束

前端不得：

- 重算核心研究逻辑
- 重定义 runtime 真相
- 把展示字段回写成研究口径
- 把 `outputs/` 当源码路径扩逻辑
- 让非主链文件回到主装载链
