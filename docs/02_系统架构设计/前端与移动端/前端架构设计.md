# 前端架构设计

## 1. 定位

前端是本系统的展示与交互层，不是研究引擎，不是运行时真相层，也不是执行判断层。

当前正式职责：

- 展示结构化研究结果与执行结果
- 承载桌面研究工作台与移动端入口
- 管理前端状态、交互流程与统一 API 调用边界

## 2. 当前桌面正式架构

当前桌面前端正式主链：

1. `frontend/index.html`
2. `desktop-shell/host.js`
3. `desktop-shell/runtime-surface.js`
4. `desktop-shell/app-shell.js`
5. `desktop-shell/*workspace.js`
6. `results-workbench/`

说明：

- `host.js` 是共享状态 bootstrap owner
- `runtime-surface.js` 是共享 helper/runtime owner
- `app-shell.js` 是页面级 init / bridge owner
- `results-workbench` 是可见结果渲染 owner

## 3. 当前结果工作台边界

当前结果工作台正式真相面：

- `comboTruth`
- `execution_contract` 或 `execution_contract_ref`
- provenance / assembly metadata（可包含 `component_source_contract`）
- 正式绩效产物
- 正式审计产物

## 4. 当前配置边界

当前 unified combo 配置口径：

- 顶层 wrapper 可保留 `asset_scope`、`asset_context`、`unified_runtime`
- 当前组件来源说明可保留 `component_source_contract`
- 当前运行行为解释必须收口到 `execution_contract`
- 前端对 unified combo baseline 采用原样透传，不再重建单资产草稿

## 5. 非目标

当前前端不应推进：

- 在浏览器中重算研究逻辑
- 用展示逻辑反向污染后端合同
- 把 `outputs/` 当作源码路径
- 让非主链文件重新获得 owner 身份
