# 移动端半自动交易运行说明

## 0. 文档定位

本文档仅描述移动端半自动交易链路的迁移期约束。

它不是移动端正式主架构文档，也不再定义系统长期真相边界。移动端正式定位以 [前端架构设计](./前端架构设计.md) 为准：

- 移动端默认只承担只读摘要与快速查看结果
- 不承担交易执行真相
- 不承担研究真相

若历史半自动交易能力继续运行，只能视为过渡流程，必须服从当前数据库与前端正式边界。

## 1. 正式边界

当前正式边界固定为：

- 移动端不得直连券商
- 移动端不得绕过桌面执行器直接改写真实持仓
- 交易生命周期真相必须进入业务事务域数据库
- 移动端页面只消费事务域与结果域的正式接口，不再以文件协议作为主真相

这意味着：

- 审批、提交、成交、拒绝、撤销等状态，应统一进入 `transactions` 生命周期主表
- 账户、持仓、现金、同步日志，应统一进入业务事务域
- `outputs/mobile_ops/*` 即使仍存在，也只能是迁移期镜像、缓存或导出产物

## 2. 当前过渡实现

当前仓库历史上曾把以下对象落在 `outputs/mobile_ops/`：

- `approval_tickets/`
- `execution_events/`
- `daily_briefings/`
- `notifications/`
- `audit_log.jsonl`

自当前文档口径起，这些对象不再被定义为正式主真相路径：

- `approval_tickets/`：应并入 `transactions` 生命周期主表，而不是继续长期作为文件主协议
- `execution_events/`：应并入 `transactions` 生命周期状态流或从属审计结构，而不是继续长期 append-only 文件化
- `daily_briefings/`：如仍保留，只能视为衍生摘要产物
- `notifications/`：当前不纳入正式数据库范围，也不再作为主系统边界文档中的正式对象
- `audit_log.jsonl`：只能视为迁移期追加审计，不替代正式数据库审计真相

## 3. 桌面执行器职责

桌面执行器当前正式职责应收敛为：

1. 消费业务事务域中的待处理交易生命周期记录
2. 依据审批状态、账户状态和执行约束推进生命周期
3. 写回提交、部分成交、成交、拒绝、撤销等正式状态
4. 记录失败原因、来源痕迹与必要审计信息

桌面执行器不再应被定义为：

- 轮询 `outputs/mobile_ops/approval_tickets/` 的文件消费者
- 以 `execution_events/` 文件作为主状态机真相的回写器

若当前实现仍保留这类文件协议，只能视为迁移期兼容壳。

## 4. 移动端页面职责

移动端页面当前应收敛为：

- 查看待处理交易摘要
- 查看当前实验与账户摘要
- 查看执行状态与错误提示
- 在迁移期内触发受限确认动作

移动端不应承担：

- 持仓真相维护
- 交易生命周期主状态机维护
- 研究逻辑重算
- 文件产物主协议写入

## 5. 数据落点原则

移动端半自动交易相关对象当前应按以下原则落点：

- `transactions`：交易生命周期主真相
- 账户与持仓快照：业务事务域数据库
- 现金账本与同步/对账日志：业务事务域数据库
- `outputs/mobile_ops/*`：迁移期镜像、缓存或导出产物

正式上不再允许把：

- 审批票据
- 执行事件
- 交易状态流

长期留在文件系统并与数据库真相并存。

## 6. 通知与日报

当前阶段：

- `notifications` 不纳入正式数据库范围
- `daily_briefings` 若继续保留，只能作为衍生摘要产物

因此移动端当前正式最低能力只要求：

- 展示结果摘要
- 展示执行状态
- 展示错误和降级提示

不要求把通知与日报能力继续扩成正式主链。

## 7. 回退原则

若需要回退移动端半自动交易能力，应优先按以下顺序处理：

1. 关闭移动端确认入口
2. 停止桌面执行器消费迁移期移动端协议
3. 停止写入 `outputs/mobile_ops/*` 的过渡产物
4. 保留移动端只读结果与摘要能力

回退后仍可保留：

- 只读移动看板
- 结果查看能力
- 与桌面端一致的术语、状态、口径展示
