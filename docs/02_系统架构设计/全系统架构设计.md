# 全系统架构设计

## 0. 文档定位

本文档描述当前仓库的正式架构边界，用于约束编码、排查和系统维护。

## 1. 系统目标

本仓库当前的正式定位是：个人多资产趋势配置系统。

约束：

- 不加杠杆
- 以可信、可审计、可解释、可复现为先
- 先稳住 A 股主线，再逐步扩展多资产

## 2. 当前正式锚点与研究纪律

- `baseline_V10.1` 是当前正式主线
- `baseline_V10` 保留为开发锚点

三窗口纪律：

- `2016-2026`：主开发窗口
- `2012-2017`：硬门槛窗口
- `2012-2026`：全周期审计窗口

## 3. 主路径

当前主路径：

- `frontend/`
- `backend/api/`
- `backend/core/`
- `backend/research/`
- `tests/`
- `openspec/`

`outputs/` 是运行产物路径，不是源码主路径。

## 4. 前端表现层

桌面前端正式主链：

1. `frontend/index.html`
2. `frontend/assets/js/desktop-shell/host.js`
3. `frontend/assets/js/desktop-shell/runtime-surface.js`
4. `frontend/assets/js/desktop-shell/app-shell.js`
5. `frontend/assets/js/desktop-shell/*workspace.js`
6. `frontend/app/results-workbench/`

## 5. API 与配置编译层

主路径位于：

- `backend/api/backtest_v2/`
- `backend/api/mobile/`

统一组合运行的正式输入约束：

- 顶层 wrapper 可包含 `asset_scope`、`asset_context`、`unified_runtime`
- wrapper、baseline、study 和其它引用对象都必须先解析为唯一 `execution_contract`
- provenance 字段不得直接进入运行分支

## 6. 回测与运行主链

正式主链应理解为：

`config_json -> compiler -> execution_contract -> DataBundle -> stage pipeline -> artifacts`

共享执行层只消费正式执行合同，不消费研究展示字段，也不消费 baseline / study / linked experiment 引用。

## 7. Unified combo 当前口径

当前 unified combo 的口径应分成两层：

- 执行真相：`execution_contract`
- 来源说明：`component_source_contract`、`component_experiments`、其它 provenance

`comboTruth` 仅属于结果展示层。

## 8. 当前收口目标

当前文档要求：

- unified combo 不再把 `component_source_contract` 当正式执行合同
- `A_STOCK_ETF_V1` replay anchor 的来源说明只留在 provenance 区
- 单次实验只能有一个执行真相

## 9. 非目标

当前阶段不应推进：

- 在前端重算核心研究逻辑
- 把 `outputs/` 当作源码层扩展业务逻辑
- 把来源字段、引用字段或展示字段误写成正式执行合同
