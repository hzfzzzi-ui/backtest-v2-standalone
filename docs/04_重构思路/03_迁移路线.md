# 03_迁移路线

## 1. 迁移总原则

### 1.1 先并联，后切换

新架构应先以 shadow / explain / budget suggestion 形式并联存在，先验证逻辑，再接管执行。

### 1.2 先上收预算，再改执行

预算权不先上收，execution path 会不断变成补丁层。

### 1.3 先拆语义，不急于先拆代码

ETF 可以先在 budget / explain 层拆成：

- defense
- core beta

再决定是否拆成多个运行时 sleeve。

### 1.4 单轮只做一个主改动

不把：

- 账户级预算
- 防守层拆分
- 现金释放
- 弱势左侧
- 执行约束

放在同一轮里同时推进。

---

## 2. 推荐迁移路线

### Phase 1：Account Allocator Shadow Mode

目标：

- 新增账户级 explain
- 输出 defense / core beta / alpha 预算建议
- 不改变实际回测行为

作用：

- 先确认账户级逻辑是否符合直觉
- 给后续预算上收建立观察面

### Phase 2：账户层接管预算

目标：

- 由账户层决定 stock 与 ETF 的预算
- 现有 `50/50` 降级为 fallback baseline 或静态参考

作用：

- 让弱势和状态切换首先表现为账户预算变化

### Phase 3：拆 ETF 的 defense / core beta 角色

目标：

- ETF 不再是万能腿
- 至少在 budget / explain 上拆成两种角色

作用：

- 让弱势防守和核心 beta 累积不再混在一个执行语义里

### Phase 4：正式切成账户配置系统

目标：

- 账户层成为唯一真相
- sleeves 变成执行消费者
- replay / audit / frontend 统一改为账户中枢叙事

作用：

- 从研究组合器真正过渡到账户配置系统

---

## 3. 各阶段风险判断

### Phase 1

- 等级：`L2-L3`
- 风险：中

### Phase 2

- 等级：`L3`
- 风险：高

### Phase 3

- 等级：`L3`
- 风险：高

### Phase 4

- 等级：`L3+`
- 风险：很高

---

## 4. 当前建议

当前最合理的起点不是再做一次大重写，而是：

1. 先把 `Account Allocator Shadow Mode` 做出来
2. 先把账户层 budget explain 做清楚
3. 再决定是否上收预算权

换句话说：

**先让账户层“看得见”，再让它“说了算”。**
