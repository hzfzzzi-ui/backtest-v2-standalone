# 02_理想架构

## 1. 核心思路

理想架构不是推翻现有趋势系统，而是把它们重新摆放到更合理的位置。

一句话：

**先由账户配置中枢决定整个账户该持有什么，再由各 sleeve 去执行。**

---

## 2. 顶层唯一真相：Account Allocator

顶层应增加一个正式的账户配置中枢，负责：

- 读取状态与风险信息
- 输出 defense / core beta / alpha 的账户级预算
- 决定状态切换时是否释放现金
- 给执行层明确预算与约束

---

## 3. 角色分离

未来的角色划分应更清晰：

### 3.1 Defense Sleeve

职责：

- 弱势承接
- 防守稳定器
- 提供现金管理与低风险停泊位

持有什么：

- 债
- 现金/货基
- 后续可扩展短债、防守层资产

### 3.2 Core Beta Sleeve

职责：

- 提供核心市场 beta
- 在弱势环境里承担少量、可解释的左侧累积

持有什么：

- 核心宽基 ETF

### 3.3 Alpha Sleeve

职责：

- 在风险允许时提供超额收益

持有什么：

- A 股个股 alpha

作用边界：

- 不承担弱势防守职责

---

## 4. 状态机的正确位置

状态机不应直接告诉某个单腿“今天买谁”，而应先告诉账户：

- 当前风险环境是什么
- 账户级预算该如何分配

例如：

- `BULL`
- `LIGHT`
- `TRANS_DOWN`
- `RISK_OFF`

这些状态应先映射成：

- defense 预算
- core beta 预算
- alpha 预算

再映射成单腿执行。

---

## 5. 弱势左侧在理想架构里的位置

允许的弱势左侧应定义为：

`防守框架里的核心宽基累积`

它应满足：

- 只在弱势环境
- 只在核心宽基
- 只用小预算
- 以小额、分段、可解释方式累积

不应演化成：

- 个股左侧
- 高弹性主题左侧
- 单次大幅抄底
- 独立反转交易系统

---

## 6. 执行层在理想架构中的角色

执行层应只负责：

1. 把账户意图落地
2. 检查可执行性
3. 回传失败原因

执行层可以说“做不到”，但不应长期替上层承担策略语义修补。
