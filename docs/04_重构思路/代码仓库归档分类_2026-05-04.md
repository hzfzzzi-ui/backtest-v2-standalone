# 代码仓库归档分类入库清单 2026-05-04

## 结论

本轮“GitHub 归档”不对应线上 issue / PR 队列。GitHub 连接器查询当前仓库 `hzfzzzi-ui/backtest-v2-standalone` 后，未发现可归档的 issue 或 PR。

当前需要入库的是本地已经整理出来的大批归档资产。归档入库应按主题分批提交，避免把归档治理和仍需验证的源码改动混在同一个提交中。

## 范围判断

- 改动等级：L1/L2 归档治理
- 不涉及：baseline 主逻辑、信号时点、成交时点、组合构建逻辑、资产池、benchmark / regime 口径
- 主要风险：工作区存在大量未提交源码改动，若整仓提交会导致归档与实现变更无法归因

## 不应混入本轮归档提交

- `backend/core/**` 的 runtime / portfolio / data 实现改动
- `backend/api/**` 的接口实现改动
- `frontend/app/**` 与 `frontend/assets/js/desktop-shell/**` 的 active 前端实现改动
- `tests/**` 的大批新增 / 修改测试
- `package-lock.json`
- 任意会影响回测口径、执行口径或研究窗口的改动

这些内容应进入独立实现提交，并附验证结果。

## 回退方式

- 若归档索引错误：只回退本文件和根目录 README 链接
- 若某批 archive 入库错误：按批次 revert 对应提交
- 不建议使用整仓 reset，因为当前工作区包含大量非本轮归档治理的既有改动
