# 文档分层与归属规则

本文定义 `docs/` 的文档归属规则。目标是区分人读说明、合同/准机器文档、机器执行材料、研究记录和历史重构材料，避免文档被错误消费。

## 1. 分层规则

| 层级 | 文档类型 | 面向对象 | 当前路径 | 是否可被测试/工具依赖 |
|---|---|---|---|---|
| H | 人读说明 | 用户、研究者、维护者 | 根目录 `README.md`、`03_策略说明/*`、`上线准备/*.md` | 只能被文档治理测试依赖 |
| C | 合同/准机器文档 | 实现者、测试、CLI | `01_系统接口模块定义/产物协议/*`、`02_系统架构设计/数据库/*合同.md`、`上线准备/合同/*` | 可以被测试校验，不得随意改字段语义 |
| M | 机器执行材料 | 运维、数据库执行者 | `02_系统架构设计/数据库/*.sql`、`*运行手册.md` | 可以被执行或按 runbook 操作 |
| R | 研究记录 | 研究者、审计者 | `05_研究记录/*`、`research/studies/*`、`research/study_journal/*` | 可以被治理测试校验覆盖关系 |
| A | 历史/重构材料 | 架构治理者 | `04_重构思路/*` | 不得作为当前实现真相 |

## 2. 当前归属

| 路径 | 归属 | 说明 |
|---|---|---|
| `docs/01_系统接口模块定义` | C + H | 接口合同、产物协议、模块边界；其中 `产物协议` 偏合同 |
| `docs/02_系统架构设计` | H + C + M | 架构说明、数据库合同、SQL 和 runbook 混合存在；必须通过根 README、文档治理和文件名区分 |
| `docs/03_策略说明` | H | 面向人的策略语义表达，不作为接口合同 |
| `docs/04_重构思路` | A | 历史判断和迁移路线，不覆盖 `01` / `02` / `openspec/specs` |
| `docs/05_研究记录` | R | study 研究索引、因子登记和研究结论归属 |
| `docs/上线准备` | H + C | 上线准备与缺口清单；`合同` 子目录为准机器合同 |
| `docs/架构关闭门禁.md` | H | 架构关闭门禁说明；后续应与 `01_系统接口模块定义/架构守门` 收敛 |

## 3. 写作规则

- 人读说明可以解释背景，但必须明确“当前事实”和“目标规划”。
- 合同/准机器文档必须写清 schema、字段、版本、owner、兼容策略和回退方式。
- 机器执行材料必须写清执行前置条件、验证方法和 rollback。
- 研究记录必须能追溯到 `research/studies/*.study.yaml`、代码 catalog、研究窗口和结论位置。
- 历史/重构材料不得反向修改当前正式口径；若发现冲突，以 `AGENTS.md`、`openspec/specs`、`docs/01`、`docs/02` 为准。

## 4. study 因子记录规则

新增或修改因子研究时，至少需要同步四处信息：

1. `backend/research/*_catalog.py`：记录 factor id、中文名、依赖、方向、as-of policy。
2. `research/studies/**/*.study.yaml`：记录 study_id、窗口、factor_ids、runner_mode 和 required outputs。
3. `research/study_journal`：记录实际运行结论、失败模式和是否推进。
4. `docs/05_研究记录/因子研究登记.md`：登记研究面、代码 catalog、study YAML 和当前状态。

没有进入登记表的因子，不得作为正式研究面或 live 发布依据宣传。
