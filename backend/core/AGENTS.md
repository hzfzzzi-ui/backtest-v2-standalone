# AGENTS.md

## 1. 目录定位

`backend/core` 是本项目的**业务核心层**。

这一层承载的不是普通工具函数，而是系统的核心骨架，包括但不限于：

- 运行时总入口壳
- 正式执行总线
- 信号生成与路由映射
- 向量化执行实现
- 组合构建、NAV、指标、记账辅助
- 核心服务聚合
- 策略定义、股票池/资产池、审计、报表、分析等主干能力

这里的改动，默认都比普通 UI、报表或脚本修改风险更高。

---

## 2. 本层的核心原则

### 2.1 保护执行边界
不得随意修改以下边界，除非先有明确 spec 并说明风险：

- execution timing
- runtime 边界
- stage pipeline 合同
- signal 进入 runtime 的方式
- portfolio 构建与记账主流程
- 任何可能改变回测口径或执行口径的核心行为

换句话说：

**凡是可能影响“信号何时生成、何时进入执行、何时成交、如何记账”的改动，默认都属于高风险改动。**

### 2.2 保护核心骨架
以下模块默认视为高风险区域：

- `engine_runtime`
- `stage_pipeline`
- `engine_vector`
- `portfolio`

这些模块的修改不得以“顺手优化结构”为名，悄悄改变核心行为。

### 2.3 优先拆热点，不顺手改行为
对于热点大文件，例如但不限于：

- `backend/core/engine_vector/strict_runtime_impl.py`
- `backend/core/engine_vector/breakout_signal_provider.py`

默认原则是：

- 优先做职责拆分
- 优先做局部收口
- 优先做边界澄清
- 不顺手扩大行为改动面

如果确实要修改这些文件的核心行为，必须先有 spec，再实现。

### 2.4 services 只做服务聚合
`backend/core/services/*` 的职责是：

- 运行编排
- 查询
- 比较
- summary
- dashboard 聚合
- 对外服务封装

不应在 `services` 层偷偷重算本应属于以下层次的核心逻辑：

- `engine_vector`
- `strategies`
- `universe`
- `portfolio`
- `backend/research`

### 2.5 core 不承接临时实验捷径
不要为了图快，把“尚未稳定的临时研究逻辑”直接塞进 `backend/core`。

新研究逻辑默认应优先通过：

- `backend/research`
- study 定义
- 受管命令入口

先接住，验证稳定后再考虑是否沉淀进 core 主干。

---

## 3. 允许做什么

在本目录中，允许且鼓励做的事情包括：

- 局部职责收口
- 热点文件拆分
- 边界澄清
- 输入输出合同补强
- 日志、错误处理、类型定义增强
- 核心路径的测试补充
- 在不改变研究口径的前提下，改善可维护性

如果改动只是在：

- 提高可读性
- 降低耦合
- 提高可测试性
- 明确边界

且**不改变系统行为**，通常可以按较低风险处理。

---

## 4. 禁止事项

你不得：

- 在没有 spec 的情况下直接修改高风险执行逻辑
- 不说明地改变 execution timing
- 不说明地改变 runtime / pipeline 合同
- 为了让代码更整齐，顺手改掉研究口径
- 在 `services` 层新增核心研究判断逻辑
- 把临时实验逻辑硬塞进 core 主干
- 把热点文件当成“万能入口”继续堆逻辑
- 在没有解释输入输出变化的情况下修改核心模块

---

## 5. 修改本层后的输出要求

凡是非微小改动，默认都必须说明：

1. 改动涉及哪些模块  
2. 是否影响以下边界：
   - runtime
   - pipeline
   - signal provider
   - portfolio
   - service contract
3. 是否改变系统行为，还是仅做结构整理  
4. 风险点是什么  
5. 如何验证  
6. 如何回退  

如果修改涉及高风险区域，还必须说明：

- 为什么必须在 core 层做
- 为什么不能先放在 research/study 路线验证
- 改动前后的输入/输出边界有什么变化

---

## 6. 默认工作方式

在 `backend/core` 下工作时，默认遵循：

- 先理解边界，再动代码
- 先缩小改动面，再实施
- 先拆热点，再谈大改
- 高风险任务先 spec，再 coding
- 优先保护回测口径与执行口径
